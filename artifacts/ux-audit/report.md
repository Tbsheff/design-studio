# Design Studio UX audit

- **Build**: `main` at `c88fc06d5`, UI built with `vite build`, server run from `apps/desktop` with `STUDIO_AGENT=mock` and a temp data dir.
- **Seed**: 5 starter projects (landing, dashboard, mobile-app, deck, form). All canvas, inspector and chat checks use "Landing page".
- **Shots**: headless Chromium through playwright, at 1440x900 and 1024x700, in dark and light. They are in `shots/`.
- **Limits**: only the mock agent ran (no real model, no publish, no LAN share). The app ran in the cloud, so every row was seen in the running app. Paths below are relative to `apps/desktop/`.
- **Severity**: blocks > looks broken > fluff > polish.
- **Verdict**: given for fluff rows only (cut / merge / hide / keep).

## Compared with Figma, Claude Design, v0 and Lovable

- **Inspector**: Figma shows about 6 sections, with icon labels and one State control. Ours shows 16 sections, 2 state rows and a sample-content tool above Layout. Neither Figma nor Claude Design puts data-fill or a11y simulation on the default inspector.
- **Chat**: Claude Design, v0 and Lovable end a run with the change summary and at most a couple of suggestions. Ours adds 3 stacks of CTAs. They also show the mode (Plan or Build) as one labeled toggle. Ours hides it in the + menu.
- **Share**: Figma, v0 and Lovable open the share link dialog in one click. Ours opens a 4-item menu that also holds Export and Move to app.
- **Home**: v0 and Lovable show one prompt, one row of starters and one project list. Ours shows the sample twice, templates 3 times and recent work 3 times.
- **Safety**: Lovable and v0 run in a sandbox. Claude Code asks before shell commands by default. Ours turns on shell, installs and auto-run by default and warns the user to turn them off.
